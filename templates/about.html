About this system

A machine learning project that estimates the probability of machine failure from operating conditions, delivered through a Flask web application.

Problem

Unplanned machine failures stop production. If operating readings can flag high-risk machines early, maintenance can be scheduled before a breakdown. Only about 3.4% of records in the data are failures, so the model must find rare events without raising too many false alarms.

Dataset

AI4I 2020 Predictive Maintenance dataset: 10,000 records of product type, air and process temperature, rotational speed, torque and tool wear. It is a synthetic benchmark dataset, so results do not transfer directly to a real factory.

Pipeline

  1. Validate input (form or CSV) against sanity ranges.
  2. Engineer features: temperature difference, mechanical power, wear x torque.
  3. Scale numeric features and one-hot encode product type, using the saved fitted pipeline.
  4. Predict the failure probability with the saved model.
  5. Apply the decision threshold and the risk bands.

The model is trained in train_model.py and only loaded here, never retrained at startup.

Data leakage decisions

Excluded: TWF, HDF, PWF, OSF and RNF. They describe why a machine failed, so they are only known after failure. Almost every failure has at least one of them set, which would make the model look perfect while being useless in practice.

Excluded: UDI and Product ID. They are identifiers, not operating conditions.

Used: Type and the five sensor readings, which are all known before a failure happens.

Risk categories (project-defined)

High: probability at or above the decision threshold ({{ predictor.threshold|pct(1) }}).
Medium: at or above half the threshold ({{ (predictor.threshold / 2)|pct(1) }}).
Low: below that.

The threshold was tuned for recall-weighted F2 on training data. These bands are a convenience for this project, not a validated industrial safety standard.

Limitations

  • Synthetic data: failure patterns were generated by rules, so real machines may behave differently.
  • Small number of failures (339), so metric estimates are uncertain.
  • Predictions are probabilities, not guarantees. A "Low" result does not mean a machine is safe.
  • Inputs outside the training range trigger a warning because the model may extrapolate poorly.
  • Recent predictions and batch results are kept in memory only and reset when the server restarts.
