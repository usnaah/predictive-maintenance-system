Why this model was selected

The selection rule was: {{ evaluation.selection_rule }}. This picked {{ evaluation.selected_model }}. The test set was not used to choose it, so the test results above are an unbiased check.

The test set has only {{ evaluation.test_failures }} failures, so small differences between models (for example one or two failures) can be due to chance. Read the comparison as indicative, not exact.

Why recall and false negatives matter

False negative = a real failure the model missed: unplanned downtime, possible damage, safety risk. False positive = an unnecessary inspection alert: some wasted maintenance time. In predictive maintenance a missed failure is usually costlier than a false alarm, so recall is prioritised. Precision still matters, because too many false alarms make people ignore the system. F2 balances the two while favouring recall. The 4:1 weighting is a project assumption, not a measured cost.
